# HW04. Промежуточный код, CFG и оптимизации Funny

Python 3.10+, стандартная библиотека. Предыдущие этапы подключаются из соседних
HW01–HW03; необходима таблица `hw01/output/dfa.json`.

Реализованы генерация типизированного трёхадресного IR, базовые блоки и CFG,
локальные константы, алгебраические упрощения, DCE, опциональный CSE,
межблочная живость, граф конфликтов и жадная раскраска временных.
Интерпретатор позволяет сравнивать результаты до и после оптимизаций.

## Запуск

Команды выполняются из корня репозитория:

```sh
python3 homeworks/hw04/src/main.py test
python3 homeworks/hw04/src/main.py ir --file homeworks/hw04/examples/arithmetic.funny
python3 homeworks/hw04/src/main.py ir --file homeworks/hw04/examples/control.funny --format json
python3 homeworks/hw04/src/main.py run --file homeworks/hw04/examples/arithmetic.funny --args '[2,3]'
python3 homeworks/hw04/src/main.py verify --file homeworks/hw04/examples/control.funny --inputs '[[0],[3],[8]]'
python3 homeworks/hw04/src/main.py verify --file homeworks/hw04/examples/calls_arrays.funny --inputs '[[[4,8]],[[-1]],[[]]]'
python3 homeworks/hw04/src/main.py ir --file homeworks/hw04/examples/bad_types.funny
```

`run` показывает `Результат: [10]` для первого примера. Результат всегда список:
Funny допускает несколько возвращаемых значений. Имя функции по умолчанию `main`,
другое выбирается через `--function NAME`. `--args` — JSON-массив аргументов,
`--inputs` — непустой JSON-массив таких наборов. Для единственного аргумента-массива
нужна дополнительная пара скобок: `--args '[[4,8]]'`.

`verify` показывает оба результата или обе ошибки и поле `equal` для каждого входа.
Лимит команд задаётся `--max-steps 100000`; он общий для всех вложенных вызовов.
Исчерпание лимита или глубины вызовов даёт `inconclusive=true`, `equal=false`.
Совпадение на конечном наборе входов не является доказательством эквивалентности
для всех программ и входов.

Обычный вывод всех трёх команд текстовый. `ir` показывает команды до/после,
таблицу метрик, CFG с метками блоков и живостью и таблицу конфликтов/цветов.
Предикаты `spec` печатаются целиком. `run` показывает функцию, аргументы и
результат. `verify` показывает результаты/ошибки до и после каждого запуска
и итог `Совпало: N из M`. Совпадение одинаковых ошибок программы также считается
сохранением поведения; неверное имя функции, число/типы аргументов и неправильный
лимит считаются ошибкой запроса и не дают успешного сравнения.

`--format json` доступен для `ir`, `run` и `verify`, если нужен машинный формат.
Например, `run ... --format json` выводит `{"result": [10]}`.

При ошибках предыдущих этапов IR не строится; сообщение содержит файл, строку,
столбец и фазу. Код завершения `0` — успех, `1` — ошибка либо несовпадение/неопределённый
результат `verify`, `2` — неправильные аргументы CLI.

## Управление оптимизациями

```sh
python3 homeworks/hw04/src/main.py ir --text 'main() returns r:int {r=2+3;}' --no-opt
python3 homeworks/hw04/src/main.py ir --text 'main() returns r:int {r=2+3;}' --passes none
python3 homeworks/hw04/src/main.py ir --file homeworks/hw04/examples/arithmetic.funny --passes const,algebra,dce
python3 homeworks/hw04/src/main.py ir --file homeworks/hw04/examples/arithmetic.funny --passes cse,dce
```

Доступны `const`, `algebra`, `cse`, `dce`; по умолчанию включены все.
`--passes` выбирает набор проходов, а не порядок. `--no-opt` имеет приоритет.

Внутри блока проход сначала подставляет известные константы и сворачивает операции,
затем упрощает алгебру, затем ищет повторные выражения. После обработки всех блоков
DCE использует актуальную межблочную живость. Проходы повторяются до стабилизации.
Таблицы констант и выражений начинаются заново в каждом блоке.

| Проход | Действие |
| --- | --- |
| `const` | После `x=5` заменяет последующие чтения `x` константой до перезаписи; вычисляет операции над константами |
| `algebra` | `x+0`, `0+x`, `x-0`, `x*1`, `1*x`, `x/1` заменяет на `x`; `x*0`, `0*x`, `x-x` — на `0` |
| `cse` | Повтор одинаковой бинарной/унарной операции заменяет копированием ранее вычисленного результата |
| `dce` | Удаляет присваивания и безопасные вычисления, результат которых не нужен ни дальше в блоке, ни на выходе |

CSE учитывает перезапись операндов и места хранения результата. Порядок операндов
сохраняется: поиск коммутативных вариантов отдельно не выполняется. Деление на ноль
при свёртке оставляет исходную инструкцию. Упрощения `x/x` и `0/x` не применяются.
DCE сохраняет вызовы, деление, чтение/обновление массива и `length`: они могут
завершиться ошибкой или не завершиться. Даже если их результат не нужен,
вычисление сохраняется. Удаление недостижимых блоков и свёртка ветвлений не реализованы.

## Формат IR и API для следующих этапов

Основной формат — JSON `funny-ir-v1`:

```json
{
  "format": "funny-ir-v1",
  "functions": [{
    "name": "main",
    "params": [],
    "returns": [{"kind": "VarDecl", "name": "r", "type": "int", "pos": {"offset": 15, "line": 1, "col": 16}}],
    "types": {"r": "int"},
    "code": [
      {"op": "label", "dest": [], "args": [], "label": "L0"},
      {"op": "copy", "dest": ["r"], "args": [{"const": 5}]},
      {"op": "return", "dest": [], "args": [{"ref": "r"}]}
    ]
  }]
}
```

`params` и `returns` сохраняют объявления из аннотированного AST, включая позиции.
`types` сопоставляет каждому исходному имени и временному его тип `int`, `int[]`
или внутренний `bool`. После оптимизаций таблица может содержать уже неиспользуемые
временные; активные временные определяются по оставшимся инструкциям.
Имена `%t0`, `%t1`, … создаются отдельно для каждой функции, не пересекаются с Funny.
Метки `L0`, `L1`, … также локальны функции.

У каждой инструкции есть `op`, список получателей `dest`, список операндов `args`.
Операнд — ровно `{"ref": "имя"}` или `{"const": число_или_bool}`.
JSON boolean отличим от целого. `dest` содержит имена, не объекты операндов.

| `op` | `dest` / `args` | Дополнительные поля и смысл |
| --- | --- | --- |
| `label` | 0 / 0 | `label`: имя метки |
| `copy` | 1 / 1 | Присваивание; массив копируется |
| `unary` | 1 / 1 | `operator`: `-`, `not` |
| `binary` | 1 / 2 | `operator`: `+ - * / == != < <= > >=` |
| `length` | 1 / 1 | Длина массива |
| `load` | 1 / 2 | Массив, индекс → элемент |
| `update` | 1 / 3 | Массив, индекс, значение → новая копия массива |
| `call` | N / M | `function`: имя; аргументы и результаты в порядке сигнатуры |
| `branch` | 0 / 1 | `true`, `false`: имена меток |
| `jump` | 0 / 0 | `target`: имя метки |
| `return` | 0 / N | Возвращает значения в порядке объявления `returns` |
| `spec` | 0 / 0 | `role`: requires/ensures/invariant/assert/assume; `ast`: аннотированный исходный предикат |

Функция заканчивается неявным `return` всех объявленных результатов; отдельного
оператора `return` в синтаксисе существующего парсера нет. Множественный вызов сначала
записывает все результаты во временные и лишь затем — в переменные-получатели.

Основные функции в `src/`:

- `ir.compile_source(text)` → `{"ir": program_or_null, "errors": [...]}`;
- `ir.generate(annotated_ast)` → IR; вызывать только после HW3 с `errors=[]`;
- `ir.format_ir(program)` → текстовый дамп;
- `optimize.optimize(program, passes=PASSES)` → новая копия IR;
- `flow.build_cfg(function)` → блоки с метками `labels`, диапазонами `[start,end)`, инструкциями, предшественниками и преемниками;
- `flow.liveness(function)` → те же блоки с `use`, `defs`, `live_in`, `live_out` как множествами;
- `flow.interference(function)` → смежность, цвета, число цветов;
- `flow.analyze(program)` → JSON-совместимые CFG, живость, графы и метрики;
- `runtime.execute(program, function, arguments, max_steps=100000)` → список результатов;
- `runtime.compare(before, after, function, arguments, max_steps=100000)` → результаты сравнения.

Генератор следующего этапа может читать `code` и `types`, строить CFG либо брать
его из `analyze`. Раскраска — отдельная карта временная → номер цвета; она не
переписывает операнды IR. Физические регистры, JVM-слоты и их ограничения выбирает
следующий этап. Исходные переменные не раскрашиваются. Число цветов не ограничено;
spill и оптимальность раскраски не заявляются.

## CFG, живость и граф конфликтов

Начало функции, каждая метка и инструкция после перехода/возврата начинают блок.
Преемники определяются последней инструкцией: два у `branch`, один у `jump`,
ноль у `return`, иначе следующий блок. Вызов остаётся внутри блока: межпроцедурный
CFG и рёбра обработки исключений не строятся.

`use` блока — имена, прочитанные до первой записи в них. `defs` — все записанные
имена. Живость считается обратным обходом до стабилизации:

```text
live_out[блок] = объединение live_in всех преемников
live_in[блок] = use[блок] ∪ (live_out[блок] − defs[блок])
```

Внутри блока инструкции просматриваются с конца. Одновременно живые временные
получают рёбра конфликта; каждый получатель также конфликтует с живыми на выходе
инструкции и другими получателями этой инструкции. В частности, это учитывает
несколько результатов одного вызова. Имена исходных переменных участвуют в
живости, но не входят в граф раскраски временных.

Жадная раскраска обходит вершины по убыванию степени, при равенстве — по имени.
Каждая вершина получает минимальный неотрицательный цвет, не занятый уже
раскрашенными соседями. Результат воспроизводим.

## Семантика и границы реализации

Исполняемые `int` — знаковые 32-битные числа с переполнением по модулю 2^32.
Литералы и входные аргументы приводятся к этому диапазону. Деление округляется
к нулю; `INT_MIN / -1` даёт `INT_MIN`. Проверяются нулевой делитель и обе границы
индекса. Присваивание, передача и возврат массивов имеют семантику значения.
Аргументы вызова вычисляются слева направо.

Для `and`, `or`, `->` принят порядок с коротким замыканием слева направо:
`and` пропускает правую часть при false, `or` — при true, импликация — при false
слева. В спецификации порядок логических операций явно не уточнён; здесь он
зафиксирован и проверен тестами. Генератор реализует его ветвлениями без SSA.

Контракты, инварианты, `assert` и `assume` сохраняются как исходные аннотации `spec`
и не исполняются интерпретатором. Это режим без runtime-проверок спецификации.
Аннотации не участвуют в живости исполняемых значений; они описывают исходную
программу, а не готовые точки проверки после оптимизации. Для последующей
верификации следует использовать исходный AST/IR до оптимизаций либо отдельно
переносить предикаты. Отсутствующие контракты не подменяются значениями по умолчанию.

Кванторы над неограниченными целыми/массивами сохраняются внутри `spec`, но
отклоняются с диагностикой IR, если встречаются в исполняемом выражении.
Их вычисление потребовало бы отдельного механизма, например SMT, который не входит в HW4.
Сохраняются синтаксические ограничения HW02/HW03, в том числе ASCII и обязательные
блоки у ветвлений и циклов. Чтение неинициализированной переменной по Funny
неопределено; интерпретатор диагностирует такое чтение, но оптимизации не обещают
сохранить диагностику неопределённого поведения.

## Сохранённые результаты

```sh
python3 homeworks/hw04/src/main.py ir --file homeworks/hw04/examples/arithmetic.funny --out-dir homeworks/hw04/output/arithmetic
python3 homeworks/hw04/src/main.py ir --file homeworks/hw04/examples/control.funny --out-dir homeworks/hw04/output/control
```

Каталог результата содержит `before.ir`, `after.ir`, соответствующие JSON,
`analysis.json`, читаемую сводку `analysis.txt` и DOT-графы CFG/конфликтов для каждой
функции до и после оптимизаций. Диапазоны блоков индексируют список `code` с нуля,
включая метки и аннотации; правая граница не включается.
Номера функций в именах DOT соответствуют порядку `functions` в JSON.
Метрики считают исполняемые инструкции (без `label` и `spec`), активные временные,
блоки и цвета. Для просмотра DOT можно использовать Graphviz, но для запуска
решения он не требуется.

## Тестирование

Подготовленные программы и ожидаемые ответы находятся прямо в `src/test_hw04.py`.
Например:

```python
self.verify("main(a:int) returns r:int {r=a+1;}", [[2]], [[3]])
```

Первый аргумент — программа, второй — наборы входных аргументов, третий —
ожидаемые списки результатов. В примере вход `a=2` должен дать результат `3`.
Вспомогательная функция `verify` проверяет выполнение до/после для всех 16
наборов оптимизаций. Ошибки, IR, CFG, раскраска и CLI проверяются отдельными
методами. `src/test_differential.py` содержит генерируемые сравнительные проверки
и независимый интерпретатор AST. Все проверки запускаются командой `test`.

Результаты проверок и измерения — в [REPORT.md](REPORT.md).
