# HW03: семантические проверки и типы Funny

Проверка имён, типов и сигнатур функций с выводом типов локальных переменных.
Вход — текст программы, выход — AST из HW02 с типами выражений и список ошибок.
Python 3.10+, только стандартная библиотека. Парсер и лексер переиспользуются
из соседних HW02 и HW01; необходима сохранённая таблица `hw01/output/dfa.json`.

## Запуск

Из корня репозитория:

```sh
python3 homeworks/hw03/src/main.py check --file homeworks/hw03/examples/good_inference.funny
python3 homeworks/hw03/src/main.py check --file homeworks/hw03/examples/good_functions.funny
python3 homeworks/hw03/src/main.py check --file homeworks/hw03/examples/good_contracts.funny
python3 homeworks/hw03/src/main.py check --file homeworks/hw03/examples/bad_semantics.funny
python3 homeworks/hw03/src/main.py check --text 'f() returns r:int { r=1; }'
python3 homeworks/hw03/src/main.py test
```

При успехе выводится JSON с `ast` и пустым `errors`. При ошибках по умолчанию
выводятся только сообщения в stderr:

```text
homeworks/hw03/examples/bad_semantics.funny:2:5: семантическая ошибка: Неизвестное имя 'missing'
```

Код завершения: `0` при успехе, `1` при ошибке. Флаг `--json` выводит полный JSON
и при ошибках. Семантические ошибки сохраняют дерево для диагностики; использовать
его для следующих этапов можно только при `errors=[]`. При лексических или
синтаксических ошибках `ast=null`: частично восстановленное дерево не типизируется.
Пути входных файлов считаются от текущего каталога, зависимости HW01/HW02 — от кода.

## Поддерживаемые типы и конструкции

Поддерживается синтаксическое подмножество HW02:

- функции, рекурсия и вызовы функций, объявленных ниже; явные типы параметров и возвратов;
- `uses` с явным типом или выводом типа, обычное и кортежное присваивание;
- чтение массива и нормализованное обновление `a[i]=v`, встроенная `length`;
- арифметика, сравнения, логические выражения, `if/else`, `while`, блоки;
- `requires`, `ensures`, `invariant`, `assert`, `assume`, `forall` и `exists`.

| Конструкция | Требования | Тип результата |
| --- | --- | --- |
| Целая константа, `-x` | для `-x`: `x:int` | `int` |
| `+`, `-`, `*`, `/` | оба операнда `int` | `int` |
| `==`, `!=`, `<`, `<=`, `>`, `>=` | оба операнда `int` | `bool` |
| `not`, `and`, `or`, `->` | операнды `bool` | `bool` |
| `a[i]` | `a:int[]`, `i:int` | `int` |
| `a[i]=v` / `ArrayUpdate` | `a:int[]`, `i:int`, `v:int` | обновление имеет тип `int[]` |
| `length(a)` | ровно один аргумент `int[]` | `int` |
| Вызов функции | число и типы аргументов по сигнатуре | объявленный тип / список типов в кортежном контексте |
| Квантор | объявленный тип связанной переменной, тело `bool` | `bool` |

`bool` — внутренний тип условий и предикатов. Переменные, включая локальные
без аннотации, допускают только `int` и `int[]`. Проверки условий, контрактов,
инвариантов и `assert/assume` требуют `bool`. Неявных приведений и перегрузок нет;
сравнения массивов и логических значений не поддерживаются.

Функция с несколькими результатами используется только в кортежном присваивании.
Число получателей и тип каждого из них должны совпадать с результатами функции.
Повтор одного получателя в таком присваивании диагностируется.

## Имена и области видимости

Глобальная таблица хранит сигнатуры всех функций, включая `length`.
Имена функций уникальны; переопределение `length` невозможно лексически в HW02.
В каждой функции параметры, возвраты и `uses` образуют одну область имён:
повтор имени между этими группами — ошибка. Разные функции имеют отдельные области.

В `requires` доступны параметры, в `ensures` — параметры и возвраты, в теле
и инвариантах — также локальные. Обращение к имени, которое ещё не объявлено
в данной области, диагностируется. Функции разрешается вызывать до их определения,
поскольку их сигнатуры собираются первым проходом.

Блоки и кванторы используют стек областей. Объявлений `var` внутри блока в HW02
нет, поэтому обычный блок не добавляет локальных имён. Переменная квантора
доступна только внутри его предиката; по правилам Funny она не может повторять
видимое имя переменной, в том числе имя внешнего квантора. После квантора имя
исчезает. Соседние кванторы могут использовать одно имя.

Параметры доступны только для чтения: запрещены присваивание, кортежная запись
и обновление элемента массива-параметра. Возвраты и локальные доступны для записи.
Локальная переменная может совпадать с именем глобальной функции, но тогда
в этой области вызов данного имени запрещён: оно обозначает переменную.

## Бонус: вывод типов

У локальной без аннотации тип сначала неизвестен (`null` в объявлении HW02).
Первое корректное присваивание связывает его с `int` или `int[]`:

```text
uses b, n
...
b = a;           // если a:int[], то b:int[]
n = length(b);   // n:int
```

Вывод работает также для результатов кортежного вызова и `a[i]=v`:
корректное обновление задаёт `a:int[]`. Последующие присваивания проверяются
на совпадение с уже установленным типом. Ошибочная правая часть не задаёт тип.
При неверном числе результатов кортежа типы получателей не выводятся.

Обход идёт в порядке исходного текста: сначала ветка `then`, затем `else`,
тело цикла проверяется один раз. Чтение локальной до вывода её типа — ошибка;
позднейшее присваивание не исправляет предыдущее чтение. У оставшейся без типа
локальной в конце функции формируется отдельная ошибка. Противоречащие типы
в разных ветках запрещены.

Это вывод статического типа, а не анализ обязательной инициализации по всем путям.
Например, после `while(false) { x=1; }` тип `x` известен как `int`, хотя цикл
не выполнится. Чтение явно типизированной, но ещё не инициализированной переменной
также не диагностируется: в спецификации Funny это неопределённое поведение.

## Формат аннотированного AST

API `check(text)` в `src/checker.py` возвращает:

```json
{
  "ast": {"kind": "Program", "pos": {"offset": 0, "line": 1, "col": 1}, "functions": []},
  "errors": []
}
```

Пример выше показывает только оболочку результата; пустая программа не является
корректным входом. Структура и поля узлов HW02 сохраняются. Добавлены:

- `type` у каждого узла выражения, включая имена в левой части присваивания;
- выведенный `type` в `VarDecl` локальных без аннотации;
- `signature: {"params": [...], "returns": [...]}` у каждой функции.

Тип выражения — строка `int`, `int[]`, `bool`. Вызов в кортежном присваивании
имеет тип-список, например `["int", "int[]"]`. Для выражения, тип которого
нельзя корректно определить из-за ошибки, используется строка `error`.
У локальной без успешного вывода в `VarDecl.type` остаётся `null`.

Например, для `r=1+2;` узел сложения содержит:

```json
{
  "kind": "Binary",
  "pos": {"offset": 23, "line": 1, "col": 24},
  "op": "+",
  "left": {"kind": "Int", "pos": {"offset": 22, "line": 1, "col": 23}, "value": "1", "type": "int"},
  "right": {"kind": "Int", "pos": {"offset": 24, "line": 1, "col": 25}, "value": "2", "type": "int"},
  "type": "int"
}
```

Позиции в этом примере соответствуют полной строке `f() returns r:int { r=1+2; }`.
Ошибки имеют поля `phase`, `message`, `pos`. Фазы: `lexical`, `syntax`, `semantic`.
Смещения с нуля; строка и столбец с единицы; CRLF считается одним переводом строки.
Отсутствующие контракты сохраняются как `null`, значения по умолчанию не вставляются.

## Ограничения

Сохраняются ограничения HW02: ASCII, одномерные массивы, обязательные блоки
у `if/else/while`, отсутствие определений формул, строк, `var` внутри блоков
и функций как значений. Литералов и создания массивов нет; массив можно получить
из параметра или результата функции. Типизация обновления ещё не гарантирует
наличие массива при выполнении.

Проверка не исполняет программу, не доказывает контракты и не проверяет границы
массива, деление на ноль, переполнение, завершение и обязательное присваивание
возвратов. Размер целой константы не ограничивается на этом этапе.
