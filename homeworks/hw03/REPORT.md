# Отчёт HW03

## Реализация

Реализован отдельный семантический проход на Python с использованием парсера
HW02 и сканера на ДКА HW01. Код предыдущих домашних работ не изменён.
Основные типы — `int` и `int[]`; `bool` используется внутри логических выражений.
Выбор соответствует подмножеству Funny из HW02 и практике P06.
Точный формат входа, аннотаций и ограничения приведены в [README.md](README.md).

## Таблицы символов

Первый проход по функциям собирает глобальный словарь сигнатур: список типов
параметров и список типов результатов. Повторное имя диагностируется, первая
сигнатура сохраняется. Встроенная `length(int[]) -> int` добавлена заранее.
Это позволяет проверять прямую/взаимную рекурсию и вызовы функций ниже по тексту.

Второй проход проверяет каждую функцию отдельно. Таблицы переменных — стек
словарей, поиск идёт от внутреннего словаря к внешнему. Запись символа хранит
объявление, роль и текущий тип. Сначала объявляются параметры и проверяется
`requires`, затем возвраты и `ensures`, затем `uses` и тело. Так ограничивается
доступность имён в контрактах. Имена параметров, возвратов и локальных проверяются
на уникальность в одном словаре функции.

При входе в блок или квантор добавляется словарь, при выходе он удаляется.
В выбранной грамматике объявления внутри обычных блоков отсутствуют; новый
символ появляется только у квантора. Повтор видимого имени квантором запрещён
правилами Funny. Локальное имя скрывает глобальную функцию; вызов скрытого
имени диагностируется. Параметры запрещены в левых частях присваиваний.

## Типизация и унификация

Выражения проверяются рекурсивным обходом: сначала дети, затем операция.
`unify` согласует типы выбранного простого подмножества: одинаковые конкретные
типы совместимы, разные дают ошибку, неизвестный тип может связываться
с конкретным. Обобщённых типов и полиморфизма нет, поэтому алгоритм с
переменными типов и occurs-check не требуется.

Неизвестный тип хранится только у локальной без аннотации. Связывание разрешено
при корректном присваивании, после проверки правой части. Чтение такой локальной
до связывания диагностируется; тип не угадывается из контекста чтения.
При несовместимом последующем присваивании исходный тип сохраняется.

Вызов проверяет все аргументы даже при неверном числе или неизвестной функции.
Аргументы сопоставляются с сигнатурой, затем проверяется допустимость числа
результатов в данном контексте. В кортежном присваивании проверяются длина списка
получателей и каждый соответствующий тип. При неправильной длине типы локальных
из такого присваивания не выводятся; при правильной длине пары проверяются
независимо, чтобы собрать несколько ошибок.

У `ArrayUpdate` проверяются тип массива, целочисленный индекс и целочисленное
новое значение. Если получатель пока без типа и индекс/значение корректны,
присваивание связывает тип получателя с `int[]`. Массив-параметр обновлять нельзя.
Так сохраняется нормализация HW02 `a[i]=v` в присваивание обновлённого массива.

Обход ветвлений идёт в порядке текста: `then`, затем `else`. Типы одной
локальной во всех ветках обязаны совпадать. Это статическая проверка типов;
анализ обязательной инициализации по путям управления не реализован.

## Диагностика и результат

Ошибки накапливаются с позициями узлов HW02. Проверяются обе стороны операции
и все операторы тела. Тип `error` подавляет производные сообщения о несовпадении
типов после уже диагностированного неизвестного имени или неверного выражения.
В конце функции отдельно диагностируются локальные, тип которых не выведен.

Каждое выражение получает `type`, локальные объявления — выведенный тип,
функции — `signature`. JSON сохраняет структуру HW02 и пригоден для дальнейшего
прохода при отсутствии ошибок. CLI показывает понятные сообщения по умолчанию
и полный JSON по `--json`. При ошибках лексики/синтаксиса семантический проход
не запускается. Чрезмерная вложенность превращается в диагностику.

## Проверки

Команды из корня репозитория:

```sh
python3 homeworks/hw03/src/main.py test
python3 homeworks/hw02/src/main.py test
python3 homeworks/hw01/src/main.py test
```

Набор HW03 включает 29 тестовых методов: 23 случая из `cases.json`, четыре
демонстрационных файла, точные аннотации и выведенные типы, сигнатуры/рекурсию,
число аргументов/результатов, массивы, контракты, вложенные области кванторов,
запрет записи в параметры, неудачный вывод и конфликты между ветками,
подавление каскадных ошибок, точные позиции CRLF, CLI из другого каталога,
лексические/синтаксические ошибки и большую вложенность. Дополнительно проверяются
150 детерминированно сгенерированных комбинаций выражений.

Результат проверки: HW03 — 29 методов, HW02 — 25, HW01 — 9, все успешно.
Эти проверки относятся к включённому набору; внешние тесты курса не запускались.

## Ограничения

Подмножество не включает строки, функции как значения, многомерные массивы,
определения формул, объявления внутри блоков и автоматические приведения.
Сравнения требуют `int`, `bool` нельзя хранить в переменной.
Нет исполнения, доказательства контрактов, проверки обязательной инициализации,
границ массивов, деления на ноль или диапазона целых констант.
Бонус реализован как вывод из первого корректного присваивания в порядке обхода,
без обратного распространения типов из последующих операторов.
