# HW02: парсер Funny и AST

Python 3.10+, только стандартная библиотека. Ветка LL: ручной рекурсивный
спуск с уровнями приоритета, факторизацией и восстановлением после ошибок.
Подключается ДКА из HW1; отдельный генератор лексера не требуется.

## Запуск

Из корня репозитория `tvdsl`:

```sh
python3 homeworks/hw02/src/main.py test
python3 homeworks/hw02/src/main.py parse --file homeworks/hw02/examples/good_basic.funny
python3 homeworks/hw02/src/main.py parse --text 'f() returns r:int { r=1+2*3; }'
python3 homeworks/hw02/src/main.py scan --text 'x = 42;'
```

`parse` выводит JSON с полями `ast` и `errors`. `scan` выводит `tokens` и
`errors`. Код завершения: `0` — успешно, `1` — есть ошибки. Путь `--file`
отсчитывается от текущей папки терминала. Вывод можно сохранить через `> ast.json`.
Входные файлы читаются с сохранением CR/CRLF и смещений исходного текста.

Готовая таблица берётся из `homeworks/hw01/output/dfa.json` независимо от
текущей папки. Она включена в репозиторий. При необходимости её можно построить:

```sh
python3 homeworks/hw01/src/main.py build
```

## Что делает программа

1. Сканер HW1 читает текст по таблице минимизированного ДКА.
2. Лексер возвращает токены с позицией, пропускает пробелы и `//`-комментарии.
3. Парсер читает токены и строит дерево AST.
4. При синтаксической ошибке записывает диагностику и пытается продолжить разбор.

Например, `r=1+2*3;` даёт такую структуру (здесь позиции опущены):

```text
Assign
  target: Name(r)
  value: Binary(+)
    left: Int(1)
    right: Binary(*)
      left: Int(2)
      right: Int(3)
```

Для просмотра ошибок и восстановления:

```sh
python3 homeworks/hw02/src/main.py parse --file homeworks/hw02/examples/bad_recovery.funny
```

В `errors` будут две ошибки: строка 2, столбец 9 и строка 3, столбец 12.
В AST останется корректный оператор `r=3;`.
Такое дерево частичное: если `errors` непустой, использовать его для компиляции нельзя.
При лексической ошибке сканирование останавливается и `ast` равен `null`.

## Поддерживаемый синтаксис

- Несколько функций в одном файле, необязательное ключевое слово `function`.
- Параметры и возвраты с явными типами `int`/`int[]`; несколько возвратов.
- Необязательные `requires` до `returns`, `ensures` после возвратов.
  Если секция указана, выражение обязательно; отсутствие секции хранится как `null`.
- Локальные через `uses x, y:int`: тип локального можно опустить.
- Присваивание, кортежное присваивание из вызова, `if`/`else`, `while`,
  `invariant`, вложенные блоки, `assert`, `assume`.
- Тела `if`, `else`, `while` обязательно в `{ ... }`: это устраняет
  неоднозначность вложенных условий и позволяет использовать LL(1).
- Числа, имена, арифметика, сравнения, булевы операции, скобки,
  вызовы функций и `length`, доступ `a[i]`, обновление `a[i]=v`.
- Кванторы `forall(i:int | ...)` и `exists(i:int | ...)` в выражениях.

`a[i]=v` сразу нормализуется в `Assign(Name(a), ArrayUpdate(Name(a), i, v))`.
`ArrayUpdate` означает новый массив с изменённым элементом, без изменения
старого массива. Это внутренний AST-узел, а не публичная функция `set`.
Исполнение, выделение памяти и фактическое копирование не входят в HW2.

## Грамматика и приоритеты

Полная выбранная грамматика — в [grammar.ebnf](grammar.ebnf).
В конце файла определены лексические токены `INT`, `IDENT`, `WS`, `COMMENT`,
а также обозначения `EOF` и `EMPTY`. Эта секция описывает работу лексера HW1;
парсер получает уже готовые токены.
Развёрнутая версия для автоматической проверки — [grammar.bnf](grammar.bnf).
Приоритеты от сильного к слабому:

| Операторы | Ассоциативность |
| --- | --- |
| Вызов, индекс, скобки | задаются структурой |
| Унарный `-` | правая |
| `*`, `/` | левая |
| `+`, `-` | левая |
| `==`, `!=`, `<`, `<=`, `>`, `>=` | без цепочек |
| `not` | правая |
| `and` | левая |
| `or` | левая |
| `->` | правая |

Левая рекурсия выражений заменена повторениями; общие префиксы
присваивания и обращения по имени факторизованы. Проверки FIRST/FOLLOW
описаны в [REPORT.md](REPORT.md); полные множества — в [LL1_TABLE.md](LL1_TABLE.md).
Тест `test_ll1_grammar` проверяет отсутствие конфликтов при выборе правила
по одному следующему токену.

## AST и позиции

Каждый узел — JSON-объект с `kind`, `pos` и собственными полями.
`pos = {offset, line, col}`: смещение с нуля, строка/столбец с единицы.
Табуляция считается одним символом. CRLF — один перевод строки;
отдельные CR и LF также поддерживаются. У бинарного/унарного узла позиция
указывает на оператор; у остальных — на начало конструкции.

| Узел | Поля помимо `kind`, `pos` |
| --- | --- |
| Program | functions |
| Function | name, params, returns, requires, ensures, locals, body |
| VarDecl | name, type (`null` для неаннотированных локальных) |
| Block | statements |
| Assign / TupleAssign | target / targets, value |
| If | condition, then, otherwise (`null`, если нет else) |
| While | condition, invariant (`null`, если отсутствует), body |
| Assert / Assume | expression |
| Name / Int / Bool | name / value / value |
| Unary / Binary | op, operand / op, left, right |
| Call | name, args |
| Index | array, index |
| ArrayUpdate | array, index, value |
| Quantifier | quantifier, variable, predicate |

Значение `Int` — строка с десятичной записью, без ведущих нулей; это сохраняет
математические целые без зависимости от ограничений преобразования Python.
Значение `Bool` — JSON boolean. Скобки не образуют отдельный узел.
Ошибка имеет `phase` (`syntax`/`lexical`), `message` и `pos`.

## Отклонения и границы HW2

- Поддерживаем и `function f(...)` из практик, и `f(...)` из спецификации.
- `_` в именах сохранён из требований HW1.
- Арифметика, условия и предикаты используют общую грамматику выражений.
  Поэтому `if (1)` и `assert 42;` синтаксически разбираются: типы проверяются в HW3.
  Импликация `->` также разрешена в предикатах как документированное расширение.
- В отличие от полной Funny, тела `if`/`else`/`while` обязаны быть блоками.
  Пишем `if (x>0) {r=1;} else {r=2;}`. Вариант `if (x>0) r=1;` отклоняется.
  Это ограничение сохраняет обязательные конструкции HW2 и устраняет конфликт `else`.
- Определения формул `name(...) => ...`, `var` внутри блока, многомерные
  массивы и Unicode не входят в выбранное подмножество.
- Пустой/пробельный файл — ошибка, как требует негативный сценарий HW2.
- Отсутствующие контракты сохраняются как `null`: семантические значения
  по умолчанию (`requires=true`, `ensures=false`, `invariant=true`)
  задаст следующий этап.
- Проверка имён, типов, числа аргументов, неизменяемости параметров,
  инициализации и границ массива относится к последующим этапам.

## Проверки и файлы

`test` запускает 24 тестовых метода. В `cases.json` — 14 примеров с ожидаемыми
позициями ошибок. Положительные AST сравниваются с вручную заданными структурами
в `src/test_hw02.py`. Отдельно проверяются приоритеты, ассоциативность, массивы,
контракты, вложенные условия, позиции, восстановление, CLI и запуск из другой папки.
Дополнительно проверяются LL(1)-грамматика, 200 случайных некорректных входов,
чрезмерная вложенность и исходные смещения CRLF при чтении файла.

| Файл | Назначение |
| --- | --- |
| src/scanner.py | загрузка таблицы HW1, позиция конца файла, EOF |
| src/parser.py | парсер, AST, диагностика, восстановление |
| src/main.py | команды parse, scan, test |
| src/test_hw02.py | эталонные AST и автоматические проверки |
| grammar.ebnf | финальная грамматика |
| grammar.bnf | развёрнутая грамматика для проверки LL(1) |
| LL1_TABLE.md | полные FIRST/FOLLOW, результат проверки конфликтов |
| cases.json | входы и ожидаемые ошибки |
| examples/ | положительные и отрицательный файлы Funny |
| REPORT.md | решения по грамматике и интеграции |
