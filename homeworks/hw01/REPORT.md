# Отчёт по HW01

## Правила токенов

Алфавит — 128 ASCII-кодов, включая управляющие символы.

| Токен | Регулярное выражение | Пропускать |
| --- | --- | --- |
| IDENT | `[A-Za-z_][A-Za-z0-9_]*` | нет |
| INT | `0\|[1-9][0-9]*` | нет |
| WS | `[ \t\r\n]+` | да |
| COMMENT | `//[^\r\n]*` | да |

Для каждого ключевого слова задано отдельное правило:
`function`, `returns`, `uses`, `while`, `if`, `else`, `true`, `false`, `int`,
`requires`, `ensures`, `assert`, `assume`, `invariant`, `length`, `forall`,
`exists`, `not`, `and`, `or`.
Название токена совпадает со словом в верхнем регистре, кроме `int`:
для него используется `TYPE_INT`, чтобы отличать от числового токена `INT`.

Операторы и разделители:
`(`, `)`, `[`, `]`, `{`, `}`, `,`, `;`, `:`, `|`, `+`, `-`, `*`, `/`,
`==`, `!=`, `<=`, `>=`, `<`, `>`, `=`, `->`, `=>`.
Символы, имеющие специальное значение в регулярных выражениях, экранируются.

Всего 47 правил. Полный список находится в `default_rules()` в `src/lexer.py`
и в поле `rules` экспортированной таблицы. При равной длине совпадения
выбирается более раннее правило. Ключевые слова стоят перед `IDENT`.

## Алгоритмы

1. Регулярные выражения разбираются рекурсивным спуском.
   Приоритет операций: повторение, конкатенация, альтернатива.
2. НКА строится методом Томпсона. Начальные состояния отдельных правил
   соединяются ε-переходами с общим стартом. Конечные состояния хранят индексы правил.
3. ДКА строится методом подмножеств. Начальное состояние — ε-замыкание старта НКА.
   Для каждого символа вычисляются переходы из текущего множества и ε-замыкание
   результата. Добавляются только достижимые множества.
4. Минимизация выполняется алгоритмом Хопкрофта. Начальные группы определяются
   результатом состояния: `None` или индекс правила. Группы разделяются по
   переходам, пока разбиение не перестанет изменяться.
5. Сканер выбирает самое длинное совпадение, запоминая последнее конечное состояние.
   Токены с `skip=True` потребляются без добавления в результат.

## Размеры и ловушка

Результат `python3 src/main.py build`:

| Автомат | Число состояний |
| --- | ---: |
| НКА | 295 |
| ДКА до минимизации, включая ловушку | 125 |
| ДКА после минимизации, включая ловушку | 122 |

В минимизированном ДКА старт имеет номер `0`, ловушка — `1`.
Ловушка не конечная; все её переходы ведут в неё же.
При детерминизации она соответствует пустому множеству состояний НКА.
Таблица содержит по 128 переходов для каждого состояния.
Символы вне ASCII направляются в ловушку функцией `DFA.step()`.

При минимизации сохраняются индексы правил. Конечные состояния разных
категорий токенов не объединяются, даже если их дальнейшие переходы совпадают.

Переход в ловушку во время сканирования завершает поиск текущего токена.
Если был найден допустимый префикс, сканер использует его и продолжает
со следующей позиции. Если такого префикса нет, выдаётся ошибка.

## Проверки

Команда `python3 src/main.py test` выполняет 9 тестовых методов; результат — `OK`.

В `cases.json` записано 35 примеров. Каждый проверяется на ДКА до и после
минимизации. Покрыты пустой ввод, пробелы и переводы строк, числа и ведущие нули,
идентификаторы с `_`, ключевые слова, операторы, комментарии, выбор самого
длинного совпадения, неизвестные символы и выход за ASCII.
Для положительных примеров сравниваются точные токены, для отрицательных — позиции ошибок.

Дополнительные проверки:

- Все 128 ASCII-символов отдельно; внутри комментария — все, кроме CR и LF.
- Полнота таблицы, допустимые номера переходов и свойства ловушки.
- Сравнение с Python `re.fullmatch` на коротких комбинациях и 1000 случайных
  строках. Генератор использует фиксированное начальное значение `1`.
- Эквивалентность ДКА до и после минимизации обходом достижимых пар состояний.
  Сравниваются метки правил для ASCII-строк любой длины.
- Конструкции регулярных выражений и известные минимальные размеры:
  `a|a` — 3 состояния, `ab|ac` — 4 состояния, включая ловушку.
- Приоритет пересекающихся правил и сохранение автомата в JSON с восстановлением.
- Отказ на ошибочных регулярных выражениях и правилах, допускающих пустой токен.

Библиотека `re` используется только в тестах как эталон.

## Особенности обработки

Идентификаторы допускают `_` согласно HW01.
Числа `00` и `01` запрещены. Для них есть отдельная проверка в сканере:
иначе выбор самого длинного совпадения позволил бы разбить строку на несколько чисел.
Комментарии заканчиваются перед CR или LF; поддерживаются LF, CRLF и отдельный CR.
Ограничение ASCII действует и внутри комментариев.

Код находится в `src/`, таблица — в `output/dfa.json`.
Команды запуска и формат таблицы описаны в [README.md](README.md).
